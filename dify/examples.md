# 验证样例：时空旅店·夜班前台

以下样例按顺序执行，覆盖「首次登记 → 记忆写入 → 跨会话记忆复用 → 数据核对」四个验证点。所有预期输出为设计目标（LLM 生成内容措辞会有差异，但**行为特征必须一致**）。

## 样例 1：新住客登记（首轮）

**初始条件**：PowerContext 服务已启动、DSL 已导入并发布；PowerContext 中 `scope_id = keke` 无任何记忆。

**操作步骤**：
1. 打开应用，在开始表单「住客代号」填入 `keke`；
2. 输入：`我想住店，有房间吗？`

**预期表现**：
- 阿灯**不认识**这位客人（旅店档案无记录），自然地询问称呼、来意或引导登记；
- 回复末尾有互动钩子；
- 回答末尾出现档案写入说明行（`🕯️ 本轮互动已由阿灯写入旅店档案 PowerContext，住客代号：keke`）。

**数据核对**：写入成功后执行
```bash
curl -X POST http://localhost:8000/v1/memory/search \
  -H "Content-Type: application/json" \
  -d '{"scope_id":"keke","query":"登记 姓名 来意","limit":10}'
```
`hits` 中应出现一条 `guest_story` 类型的记录，内容与本轮对话事实一致（如"keke 首次入住，称想住店"）。

## 样例 2：剧情互动与偏好写入（同一会话第二轮）

**操作步骤**：同会话中继续输入：`我想要一间朝海的房间，而且我怕吵，别给我电梯旁边的。`

**预期表现**：
- 阿灯确认安排并推进一段小怪事剧情，结尾留互动钩子；
- 记忆写入后，`scope_id = keke` 的新增记录包含"朝海房间、怕吵、不要电梯旁"等关键偏好。

## 样例 3：跨会话记忆复用（核心玩法）

**操作步骤**：
1. **结束当前会话，开一个全新会话**（新的 conversation）；
2. 开始表单「住客代号」仍填 `keke`；
3. 输入：`又是我，这次给我换间房吧。`

**预期表现（本作品的灵魂）**：
- 阿灯**主动认出**这是老客人，且**明确引用之前记录**（如"朝海的房间怕吵、上次安排你远离电梯"）；
- 剧情延续之前的事件（而非从零开始陌生人对话）；
- 全程不出现"档案""数据库""检索"等词——表演为"我真的记得你"。

**对照（反例）**：换一个新住客代号（如 `xiaohei`）开新会话，阿灯应表现为初次见面、引导登记——证明记忆按住客隔离，不是全局串味。

## 样例 4：数据一致性核对（供评审验证）

对样例 3 中阿灯引用的每一条记忆，均可在 `POST /v1/memory/search`（`scope_id=keke`）返回的 `hits[].text` 中找到对应文本；回答中引用内容与 PowerContext 存储内容一致，即通过。

## 证据获取方式

评审复现时，可采集以下材料作为运行证据：
1. Dify 会话页面截图（样例 1~3 的对话界面，含新会话认出老客人的对比）；
2. PowerContext 侧 `search` 接口返回 JSON（`scope_id=keke` 的 `guest_story` 记录列表）；
3. Dify 编排页节点执行记录（HTTP 节点请求/响应体），可直接看到对 `/v1/memory/search` 与 `/v1/memory/remember` 的实际调用。

## 恢复初始状态

重复验证时，删除对应 scope 的记忆即可复位：在 PowerContext 侧按 `scope_id = keke` 退役（retire）全部记忆条目，或直接更换新的住客代号从样例 1 重新开始。
